## 一、快速开始（3 步）

```bash
# 1. 启动平台
npm run dev

# 2. 生成外部数据源（独立 SQLite 库，4 表 120 行）
python demo-data/build_external_db.py

# 3. 一键装载全功能验证数据（幂等，可重复运行）
node demo-data/load.mjs
#    期望输出：通过 41/41
```

- 默认账号：`chen.xingye / ontos@2026`
- 浏览器打开 `http://localhost:5174`，按下方矩阵逐项体验
- ⚠️ **空间提示（重要）**：平台是多空间隔离的。`load.mjs` 把**绝大多数 DEMO_ 数据装在组织空间「星辰智造集团」**（`sp-org-default`），只有 6 条消费数据 + 扫描明细装在**个人空间「陈星野的个人空间」**。顶栏可切换空间；若某页列表为空，先确认当前空间是否正确（尤其从「Contour 消费分析」切回来后）。
- **清理**：`node demo-data/load.mjs --clean`（只删 `DEMO_` 前缀数据，不动种子数据）

## 六、注意事项（诚实边界）

- **2 个演示页**：调度优化 / Apollo 部署需外部系统，保持演示态且按钮明确反馈，不假装成功（不计入 live）。
- **时序曲线**：基于真实设备健康度的确定性模拟历史（非真实采集），页面已标注；告警规则/通知是真的。
- **管道拓扑**：固定 7 节点结构示意（已标注），管道 CRUD/校验/发布/运行记录是真实的。
- **AI 识别**：视觉/文本模型依赖外部网关；网关不可用时 `/scan/recognize-text` 有平台 AI 网关兜底，`/knowledge/docs` 分块有本地哈希向量降级（`mode=local`），不会伪造成功。
- **数据连接非 SQLite 类型**：仅登记参数，不发起真实连接（诚实标注）。
- `load.mjs` 只写 `DEMO_` 前缀数据，`--clean` 不会动种子数据；外部库 `external/enterprise.db` 是独立文件，删除它即可完全移除外部数据源。
